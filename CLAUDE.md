# sefer-forge — conventions for Claude sessions

## What this repo produces
Hebrew **books** (several — one folder each under `books/`) assembled from **discourses**. Each discourse is built up across multiple **sessions**. A discourse later becomes (typically) a **chapter** in a book.

Two kinds of discourse (`type:` in its `meta.yaml`):
- **images+voice** (default) — photos of a sefer + a voicenote → `ocr.md`, `commentary.md`, `section.md`.
- **voice-only** — a recorded shiur, no photos → `transcript.md` per session (e.g. `002-shaar-hayichud`).

## Unit hierarchy
- **session** = one ingestion batch (~N images + 1 Hebrew voicenote, or 1 recorded shiur).
  Location: `discourses/<NNN>-<slug>/sessions/<MMM>/`
  Outputs: `ocr.md`, `commentary.md`, `section.md` — or, voice-only, `transcript.md`.
- **discourse** = 1..N sessions woven into a cohesive essay.
  Location: `discourses/<NNN>-<slug>/discourse.md`
- **chapter** = 1..N discourses assigned in `books/<book>/structure.yaml`.
- **book** = `books/<book>/` (structure, metadata, front/back matter) → compiled at `compiled/<book>.md` → rendered at `output/<book>.docx` by `bash scripts/build-all.sh <book>`.

## Source-of-truth rules
- **Never edit**: raw audio (`.m4a` etc.), image files, `*.raw.txt` (raw Whisper), the reference works in `sources/` (Sefaria exports of עץ חיים, פרי עץ חיים; catalog `sources/sources.yaml`, look-ups with `scripts/source-lookup.py`).
- **Photos and recordings are local only**: `.gitignore` keeps `images/` and the audio in `voicenotes/` out of git; never `git add -f` them or push them. The transcripts beside the audio (`*.raw.txt`, `*.timed.txt`) are committed. `ocr.md` is final once the session's ingest has matched it against the voicenote (`prompts/02-ingest-session.md` Step 2): before that it is corrected against the photo only, after it never. A session whose text came from a digital edition (pasted from chabadlibrary.org) has no photos: its `ocr.md` holds the text exactly as given, one `## Source: <url>` section per page.
- **Generated but editable**: `commentary.md`; `section.md` of older sessions (no plan).
- **`section.md` from a plan**: when a session has `section-plan.yaml`, `section.md` is built from it plus `ocr.md` and `commentary.md` by `scripts/build-section.py` (frontmatter `built_from: section-plan.yaml`). Edit the plan and rebuild; never the built file.
- **Reports, regenerated by scripts**: `review.md` (transcript-diff), `ocr-match.md` (ocr-match), `references.md` (build-references, from the session's `references.yaml`), `refined.md` (refined-text: a narration's cleaned transcript with the readability and style passes applied, before it is laid out). The teaching pass (`teaching:`, `prompts/teaching-pass.md`, the last step of every narration) adds `section.teaching.md` and `refined.teaching.md` (generated), an opening part's `<name>.teaching.md`, and its working notes `teaching-notes.md`. The teaching text is what prints (pamphlet, `discourse.md`, book); the lesson text before it prints with `--lesson` (`discourse.lesson.md`, `output/pamphlets/lesson/`). Abbreviations a reader expands aloud: `glossary/abbreviations.yaml`.
- **Hand-edit freely**: `discourse.md` — this is where you polish for flow across sessions.
  **Exception — voice-only discourses:** `discourse.md` is regenerated on every build from `sessions/*/transcript.md` (+ `intro:` / `skip_sessions:` in `meta.yaml`). Edit the transcripts, never that `discourse.md`.
- **Whisper corrections**: `glossary/whisper-fixes.yaml` (shared) — `transcribe.py` / `apply-fixes.py` turn `*.raw.txt` into `*.fixed.txt`. Add recurring mis-hearings there.
- **Transcript cleanup** (`.fixed.txt` → `commentary.md` / `transcript.md`) follows `prompts/transcript-review-rules.md`; `python scripts/transcript-diff.py <session>` writes `<session>/review.md` listing every word changed relative to Whisper.
- **Never hand-edit**: anything in `compiled/` or `output/`.

## Markdown conventions
- **Snapshot marker**: leading/trailing `...` on text that was cut off in the photo.
- **RTL wrapping**: every Hebrew paragraph is wrapped in `[text]{dir="rtl"}`.
- **`section.md` layout — paired (the standard, `layout: paired` in its frontmatter, built by `scripts/build-section.py`):** the title block; `## הַנֹּסַח וְהַבֵּיאוּר` as cuts of the text (`::: {custom-style="Nusach"}`), each followed by the explanation of it (`::: {custom-style="Commentary"}`, unboxed, no labels); the print's notes; `## נְקֻדּוֹת מַפְתֵּחַ`. Pages print text on top, explanation below (`docs/print-standard.md`). The plan's `edits:` hold the readability pass (`prompts/readability-pass.md`), its `style:` the style pass (`prompts/style-pass.md`); both change only what prints.
- **Older `section.md` layout = three named sections** (sessions not yet moved; skill `paired-layout` moves them):
  1. `## הַנֹּסַח הָעִקָּרִי` — full OCR text as flowing `[...]{dir="rtl"}` paragraphs; bold key transitional words; preserve `...` snapshot markers and `<!-- UNCLEAR: ... -->` flags; no `{.underline}` markup here.
  2. `## נְקֻדּוֹת מַפְתֵּחַ` — 5–8 bold topic labels each followed by a `>` blockquote of the key source passage, both in `{dir="rtl"}`.
  3. `## בֵּיאוּר וּפֵירוּשׁ` — sequence of `::: {custom-style="Commentary"}` fenced divs, one per voicenote topic, each opening with `**[■ ביאור — <topic>]{dir="rtl"}**` followed by the cleaned voicenote commentary. `scripts/polish-docx.py` renders each as a framed box in smaller type. (Sessions ingested before 2026-10-15 use single-column `+---+` grid tables; leave them as they are.)
- **YAML frontmatter** on every `section.md`, `transcript.md` and `discourse.md` — must be valid YAML (escape `"` inside double-quoted values: `חב\"ד`).
- **`transcript.md`** (voice-only): frontmatter `title` becomes a `#` chapter heading (new page), `subtitle` an italic line; body uses `##` sub-headings, `>` for quoted source text, `[^N]` footnotes (numbering restarts per session; the build keeps them unique). The pamphlet pairs each heading and quoted passage (on top) with the explanation that follows (below), so quote the passage read as `>` at the point it is read.
- Hebrew stays Hebrew — never translate unless explicitly asked.

## Hard DOs and DON'Ts

- ❌ **Do NOT invoke docx/pptx/xlsx skills, and do not write per-discourse python-docx build scripts.** All rendering goes through `scripts/build-all.sh <book>` (pandoc + `templates/book-template.docx` + `scripts/polish-docx.py`). Typography changes go in `scripts/create-template.py` or a book's `polish:` block in `metadata.yaml`. The exceptions are the Shivchei HaBesht booklets and the standalone pamphlets (below), which print to PDF through Chrome.
- ❌ **Do NOT transcribe audio via chat.** Always run `python scripts/transcribe.py <session>` first; you then clean up the `.raw.txt` output.
- ❌ **Do NOT hand-edit `compiled/` or `output/`.**
- ❌ **Do NOT edit `*.raw.txt`.** `*.fixed.txt` is regenerated — don't edit it either.
- ❌ **Do NOT auto-overwrite `discourse.md`** if it has content beyond the frontmatter skeleton (the assemble script enforces this; respect it).
- ✅ **DO** preserve `[...]{.underline}` markers and `...` snapshot markers verbatim.
- ✅ **DO** flag unclear text in `ocr.md` as `<!-- UNCLEAR: ... -->` rather than guessing.

## Checking work
- `python scripts/session-status.py [path]` — where each session stands and its next step (also after a crash: an interrupted transcription resumes by rerunning `transcribe.py`).
- `python scripts/check-session.py [path]` — every rule above that a script can check; run it after changing a session. A project hook runs it after each edit of a session file and reports errors.
- `python scripts/proof-pdf.py <pdf>` — a printed PDF against `docs/print-standard.md` (fonts, palette, leaks, margins, stranded headings, page numbers), plus spread images for the visual review. The book's PDF comes from `bash scripts/docx-to-pdf.sh output/<book>.docx`.

## Cloud sessions

Rerun it by hand if a container lacks any of these. Chrome is found on the PATH; the Whisper model downloads on the first transcription.

## When the user says...
- "status" / "where are we" / "what's next" → skill `session-status`.
- "new discourse" → use `prompts/01-new-discourse.md`.
- "new session" / new photos + recording for a discourse → skill `new-session`.
- "OCR" / a photo added or replaced → skill `ocr-session`.
- "ingest session" / "process this session" / "continue" → skill `ingest-session` (`prompts/02-ingest-session.md`, images+voice) or, for a voice-only discourse, `prompts/02v-ingest-voice-session.md` (skill: `ingest-voice-session`).
- "new lesson" / "ingest voice session" / "next shiur" → `prompts/02v-ingest-voice-session.md`.
- "assemble discourse" → skill `assemble-discourse` (`prompts/03-assemble-discourse.md`).
- "add to chapter" / "assign to chapter" → skill `assign-chapter` (`prompts/04-assign-to-chapter.md`).
- "build book" / "render" → skill `build-book` (`prompts/05-build-book.md`; `bash scripts/build-all.sh [book]`, no book = all books).
- "grow the glossary" / "update whisper fixes" → skill `grow-glossary` (`python scripts/glossary-candidates.py`).
- "build booklets" → `python scripts/build-booklets.py [N ...]`: themed A5 PDFs of `shivchei-habesht-simple.md` in `output/booklets/`. Grouping in `booklets/booklets.yaml`, glossary in `booklets/glossary.yaml`, layout in `templates/booklet.css`.
- "English booklets" / "French booklets" / "translate the booklets" → skill `translate-booklets`; `python scripts/build-booklets.py --lang en|fr [N ...]` (→ `output/booklets/en|fr/`), from `shivchei-habesht-simple-en.md` / `-fr.md`: translations of the Hebrew booklet text, sentence by sentence, under `prompts/translate-stories-rules.md` (names and terms table); `python scripts/check-translation.py <file>` holds them to the Hebrew's sections, paragraphs, summaries and MATURE flags. Titles in `booklets.yaml` (`en:` / `fr:`), glossaries `booklets/glossary-en.yaml` / `-fr.yaml`, layout `templates/booklet-latin.css` over `booklet.css` (EB Garamond in `templates/fonts/`). A change to a Hebrew story is carried into both translations.
- "narration" / "video" / "YouTube" / "another episode" → skill `narrate-video` (rules `prompts/narration-rules.md`, episodes made listed there, ideas in `docs/backlog.md`): `python scripts/build-narration.py booklets/narration/<name>.yaml` (`--script` text only, `--frame` picture only, `--video` video only, `--sample v1,v2` voices, `--say <word>` pronunciation) reads the English or French booklet stories a plan names with the free Kokoro voice (`requirements-narration.txt`), the Hebrew ones with a Google Cloud voice kept inside its free allowance (`GOOGLE_TTS_API_KEY`) → `output/narration/<name>/` `video.mp4` (one plain title card for the whole reading), `thumbnail.jpg`, `narration.mp3`, `narration.srt`, `chapters.txt`, `script.txt`. No contents list or glossary is read; MATURE stories are refused. Respellings for names: `booklets/narration/say-en.yaml` / `say-fr.yaml` (shared; check a plan with `--names`). A French or Hebrew episode starts from its English plan: `python scripts/narration-french-plan.py <english plan> <name> "<title>" [--lang he]`, then its `# TODO`s by hand (Hebrew abbreviations: `say-he.yaml`). `output/` is not in git: hand the files over.
- "English episode" / "shiur in English" / "next shiur in English" / "narration status" → `prompts/render-english.md`: `python scripts/narration-status.py [discourse]` says, per discourse, which parts have English (`transcript-en.md` / `introduction-en.md` beside the Hebrew, fingerprinted to it: STALE when the Hebrew changes), which episode plan reads them (`parts:`), and whether it is approved, built and on YouTube; then the next step. Render faithfully in plain English, no additions and no transliteration (terms translated by the table in the prompt; only names kept, checked with `--names`), and send Ronnie the script and an audio sample; a plan of `parts:` is recorded only after `approved: <date>`. A newly ingested shiur ends with this step offered.
- "publish to YouTube" / "upload" / "next uploads" → `docs/youtube-publishing.md`: `python scripts/youtube-publish.py queue | auth | publish --build | sync` puts the episodes on the channel, private, two a day (1 English, 1 French; Hebrew waits for a Hebrew voice), with their title-card thumbnails, in the order of `queue:` in `booklets/narration/youtube.yaml` (the record of what is up; commit it into `main` after every session). Sign-in: `YOUTUBE_CLIENT_ID` / `YOUTUBE_CLIENT_SECRET` in the environment, and either `YOUTUBE_REFRESH_TOKEN` (lasting, from `scripts/youtube-signin-local.py`, which the user runs once on their own computer: setup step 8) or a code the user enters at google.com/device (`auth`, each session). Every new episode is published as part of making it.
- "text on top, explanation below" / "pair the layout" / an older section → skill `paired-layout`.
- "words that don't make sense" / "clean up the explanation" → the readability pass, `prompts/readability-pass.md` (also a step of every proof).
- "refine the transcript" / "take out the conversational" (a narration not yet laid out) → the readability and style passes as `edits:` / `style:` in `commentary.md`'s frontmatter, then `python scripts/refined-text.py <session>` → `refined.md`; `commentary.md` stays the faithful transcript. Then the teaching pass (`teaching:` in the same frontmatter → `refined.teaching.md`; an opening part made from it gets its `<name>.teaching.md`).
- "teaching pass" / "instructional" / "turn it into a commentary" / "not a transcript of a lesson" / "cut it by half" → skill `teaching-pass` (`prompts/teaching-pass.md`): the last step of every narration (ingest step 7, voice-only step 8), after the style pass; the explanation rewritten as a written commentary on the text (about half), understood in writing first (`teaching-notes.md`), recorded as `teaching:` with `python scripts/apply-teaching.py <session> --draft|<file>`, checked with `python scripts/check-teaching.py <discourse>`. It is what prints; `--lesson` prints the text before it. Sessions ingested before 2026-11-08 only when asked.
- "less conversational" / "style pass" / "make it read like writing" → `prompts/style-pass.md`, a step of every new session before the teaching pass: `style:` in the plan (or the transcript's frontmatter), applied after `edits:`; the quoted readings never change. Not run on older sessions unless asked.
- "proof" / "review the PDF" / "check formatting", and before any PDF is called ready → skill `proof-pdf` (`docs/print-standard.md`, `python scripts/proof-pdf.py <pdf>`). No PDF goes to the user for acceptance testing without it.
- "pamphlet" / "standalone" / "publish session N on its own" → `python scripts/build-pamphlet.py <session-or-discourse> --png` (skill: `publish-pamphlet`): an A5 PDF in `output/pamphlets/` of one session, or of a whole discourse behind a contents page; it prints the teaching text where a part has one (`--lesson`: the text before it, into `output/pamphlets/lesson/`). Cover text from the book listing the discourse, overridden by `pamphlet:` in its `meta.yaml`; layout in `templates/pamphlet.css`.
- "new book" → `./scripts/new-book.sh <slug> "<title>"`, then fill `books/<slug>/structure.yaml`.
- a narration of one box of a reading pack ("עץ חיים 3", "the next הערה") → skill `new-session`, starting the session with `python scripts/box-session.py <discourse> <box>` (its `ocr.md`: the text's stretch and the box's passage as the pack prints them; a starter plan), then `ingest-session` to the teaching pass. Recordings from Google Drive: the `new-session` skill (`scripts/drive-decode.py`, or a share link and curl for large files).
- "the Etz Chaim references" / "the sources he cites" / "before I record" / a pasted text with "bring its sources" → skill `references-pack` (`prompts/references-pack.md`): the session's text broken after each citation, the cited passage from `sources/` below it with lines before and after and the referred-to words highlighted (`references.yaml` → `python scripts/build-references.py <session>` → `output/references/<discourse>-<session>.pdf`, A4, `templates/references.css`), proofed, then checked against the request (step 6) before it is handed over.
